# CargaPronto: Customer Segmentation and Delivery Delay Prediction

Учебный проект Яндекс Практикума (Data Science, «Обучение без учителя»): сегментация клиентов K-Means и прогноз риска задержки доставки CatBoost. Система поддержки решений для логистов: в момент оформления заказа модель выдаёт вероятность срыва SLA.

## Задача

Логистический оператор CargaPronto: 55% заказов доставляются с задержкой, штрафы по SLA съедают бюджет. Гипотеза заказчика: риск создают не сбои логистики, а профиль клиентов («чёрные дыры» на карте, возвратники). Проверить гипотезу, сегментировать базу и построить бинарный классификатор задержки.

- **Метрика**: ROC-AUC (планка заказчика: > 0.75)
- **Модели**: логистическая регрессия (прозрачная нижняя планка) и CatBoost
- **Данные**: две выгрузки из ERP — заказы (36k+, 24 признака) и профили уникальных клиентов (RFM: recency, total_orders, total_sales, return_rate и др.)

## Результаты

| Конфигурация | Val ROC-AUC | Test ROC-AUC |
|---|---|---|
| Logistic Regression (база) | 0.7257 | 0.7290 |
| CatBoost (база) | 0.7503 | 0.7570 |
| CatBoost + кластеры (geo 20 × RFM 12, числовые) | 0.7669 | **0.7721** |

- Планка заказчика (> 0.75) пройдена: кластеризация добавляет +0.015 к тесту базового CatBoost
- **Гипотеза подтвердилась наполовину**: поведенческий профиль работает (beh_cluster: 15.4% важности), география почти нет (geo_cluster: 6.0%; доля задержек по зонам одинакова, 54.7–55.5%)
- Главные драйверы риска в самом заказе: режим доставки (First Class опаздывает в 95% заказов, Standard Class в 38%) и час оформления (21.9% важности)
- Контрастный сегмент «проблемные возвратники» (return_rate ≈ 0.92): их заказы почти не опаздывают (13.6%) — проблема в возвратах, не в сроках
- Операционные пороги: 0.50 → recall 60% / precision 83% (рабочий), 0.70 → precision 88% (уровень срочных мер, ~34% заказов)

## Методология

- **Утечки**: RFM-агрегаты ERP выгружены «на всю историю» и могут включать заказы после прогнозируемого момента — зафиксировано как ограничение; для продакшена агрегаты пересчитываются на момент заказа
- **Кластеризация без утечки**: scaler и оба K-Means обучены только на train-клиентах; val/test размечены ближайшим центроидом; GroupShuffleSplit по customer_id исключает пересечения клиентов между выборками
- **Выбор K**: перебор geo_k × rfm_k из {4, 8, 12, 20} × {6, 12, 20, 30}; K трактуется как слабый гиперпараметр (соседние конфигурации отличаются на 0.002–0.004)
- **Валидация**: val использовалась и для выбора кодирования кластеров, и для перебора K, поэтому несмещённая оценка качества — тестовая
